# Quirks of the Plane MCP (probed 2026-10-07)

Each line says how it was established. "Tested" = observed live, "schema" = read from the tool schema only, "untested" = could not be checked.

| # | Quirk | Evidence | Rule for the skill |
|---|---|---|---|
| 1 | Items of an **archived** project are invisible to `list_work_items` (E2EWEB: summary says 26 items, `list_work_items(project_id)` returns total 0). `list_projects` still shows it with `archived_at`. Its intake queue is still readable. | tested | Say "archived, N items per summary" instead of reporting 0. Never report an archived project as empty. |
| 2 | `list_work_items` pages with `total` + `next_offset` (limit 5 of 18 returned next_offset 5; last page returns null). | tested | Loop until `next_offset` is null; state the row count. |
| 3 | List tools using cursors (`list_projects`, `list_intake_work_items`, ...) return a `next_cursor` even on the last page. The reliable flag is `next_page_results`. | tested | Stop on `next_page_results: false`. |
| 4 | `add_work_item_relation(work_item_id=X, relation_type=blocked_by, related=[Y])` means **X is blocked by Y**. The response echoes the *related* items, not X. Y then lists X under `blocking`. | tested | Read back with `list_work_item_relations` on X. |
| 5 | `create_state` accepts any group (tested `started`); slug is auto-derived (`blocked`); a state with no items deletes cleanly. Behaviour with items assigned to a custom state was not exercised. | tested (create/delete), untested (items) | Resolve "done" by `group == completed`, never by the name "Done". |
| 6 | Dates passed to `create_cycle` as `YYYY-MM-DD` are stored as UTC instants (`2026-10-07T13:00:01Z` for Oct 8 Melbourne, end `...12:59:00Z`) and the cycle's `timezone` is `UTC`. Work item dates stay plain `YYYY-MM-DD`. | tested | Convert cycle dates to the project timezone when reporting. |
| 7 | Intake items not yet accepted sit in state group `triage`, which is **not** in the `state_groups` filter enum. Intake `status`: -2 pending, -1 rejected, 0 snoozed, 1 accepted, 2 duplicate. | tested | Read the queue with `list_intake_work_items`, not `list_work_items`. |
| 8 | `update_work_item` treats null as "unchanged": no field can be cleared (target_date, parent, estimate). `assignee_ids` and `label_ids` replace the whole set. | schema | Always `get_work_item` first and resend the labels or assignees you keep. Tell the user a clear is not possible via MCP. |
| 9 | `get_estimate` returns a 404 error when the project has none. | tested | Treat 404 as "no estimate", not a failure. |
| 10 | `get_cycle` counts include parent items. A cycle with 3 parents and 15 steps reports `total_issues: 18`. | tested | Report "leaf items" when parents are in the cycle. |
| 11 | `search_work_items` returns only id, name, sequence_id, project identifier. | tested | Follow with `get_work_item` for state. |
| 12 | `list_work_items` rows carry `key`, `state_name` and `state_group`; `create_work_item` / `update_work_item` responses carry the state UUID only. | tested | Do not print state names from write responses; use the list row. |
| 13 | `archive_cycle` only after the end date, `archive_module` only when completed/cancelled, `transfer_cycle_work_items` only from an ended cycle. | schema | Check status before offering archive. |
| 14 | Intake can only be created when the project has `intake_enabled`. PLANESKILL has it off. | schema + project record | Offer to enable intake before `create_intake_work_item`. |
| 15 | Comments are stored as given HTML with `access: INTERNAL`. | tested | Use `<p>`, `<ul>`, `<code>` only. |
| 16 | Permission limits for guests or non-admins were **not tested**: this workspace has one member (admin). | untested | Say so in reports; surface 403 errors verbatim. |
| 17 | At first probe the workspace had no agents. `list_agents` defaults to `status=active`, so it also looks empty when only archived agents exist. | tested | Always pass `status=all` when checking whether an agent exists. Agent tools were later exercised in the Step 12 run (#18-26). |

## Added by the Step 12 end-to-end run (2026-10-07, scratch project PMSKE2E, archived afterwards)

| # | Quirk | Evidence | Rule for the skill |
|---|---|---|---|
| 18 | Leaving a completed state clears `completed_at` (Done -> In Progress returned `completed_at: null`). Entering completed sets it server-side. | tested | Say that reopening clears the completion time. |
| 19 | Comments made through this MCP are attributed to the **token owner** (`actor` = the human), even when written "as" an agent. The agent has no author identity via the MCP. | tested | In agent mode prefix comments with the agent handle, e.g. `[scratch-qa] ...`. |
| 20 | `create_agent` with `project_ids` makes the bot a project member at once (it appears in `list_project_members` with `is_bot: true`) and it can be passed as `assignee_ids` on `create_work_item`. `get_agent_task_brief` returned the definition plus the item and wraps item text in `BEGIN/END WORK ITEM DATA` markers. `list_agent_work_items` returned the item. | tested | Pass the agent's `bot_user_id`; trust the brief's data markers. |
| 21 | `archive_agent` sets status `archived` and empties `project_ids`, but the items assigned to it stay assigned (`assigned_open_count` 1 after archive). | tested | Re-assign open items before archiving an agent. |
| 22 | `archive_cycle` before the cycle is completed returns 400 "Only completed cycles can be archived"; `archive_module` before status completed/cancelled returns 400. `update_module(status=completed)` then `archive_module` succeeds. | tested | Complete the module first. A cycle cannot be archived early, so `close` leaves it and says so. |
| 23 | `create_cycle` with a start date of today stores start = now (`23:06:39Z`), unlike a future start date (`13:00:01Z` for Melbourne midnight). | tested | Expect a start-of-day shift only for future dates. |
| 24 | Accepting an intake item puts it in the project's default state (Backlog) and it then appears in `list_work_items`; a snoozed item stays in group `triage` and does not appear. `snoozed_till` is echoed back. | tested | After accept, read back with `get_work_item`. |
| 25 | `create_project(intake_enabled=true)` works at creation time (intake view on, `create_intake_work_item` succeeded). | tested | Enable intake at creation when the user wants a queue. |
| 26 | `archive_project` returns `{success: true}`; the project then shows `archived_at` in `list_projects`. | tested | Confirm before archiving; it is reversible with `unarchive_project`. |

## Added by the extension run (scratch project PMSKX, designer + developer agents, 2026-10-07)

| # | Quirk | Evidence | Rule for the skill |
|---|---|---|---|
| 27 | `search_work_items("PMSKX-7")` does not filter by key: it matched sequence number 7 in three projects (PMSKX, PLANESKILL, AGENT). Text search (`login`) with `project_id` works. | tested | Look up a key with `get_work_item(key=...)`; use search only for words, scoped to a project when known. |
| 28 | `list_work_items(name_contains=...)` filters by name and returns state, so `find` can use it when state or assignee is also wanted. | tested | Prefer it over `search_work_items` + `get_work_item`. |
| 29 | `list_work_item_relations` returns only `{project_id, issue_id}` per relation, with no key, name or state. `add_work_item_relation` echoes names and state of the related item, but the list does not. | tested | To check "all blockers completed", call `get_work_item` on each `blocked_by` id. |
| 30 | `get_agent_task_brief` has the definition and the item (links, comments) but no relations. For an item not assigned to that agent it returns 404 `not assigned to this agent`. | tested | Agents must call `list_work_item_relations` themselves; on 404 check `list_agent_work_items`. |
| 31 | `list_agent_work_items(state_group=open)` lists every open assigned item, including ones blocked by unfinished items; the order is not by priority or readiness. | tested | Rank by priority, then drop items whose blockers are open. |
| 32 | A paused agent cannot be newly assigned: `create_work_item` and `update_work_item` return 400 `Agent(s) @x are paused or archived and cannot receive new assignments`. `accept_assignments=false` returns the same message (it says "paused or archived" although neither is true). | tested | Read the agent's `status` and `accept_assignments` before assigning. |
| 33 | `update_agent(status=paused|active)` and `accept_assignments` do not bump `version` and make no revision. A change to `instructions_md` (or other definition fields) bumps the version and writes a revision with a full snapshot and `change_note`. Workflow step ids are kept across updates. | tested | Always pass `change_note` on definition changes; `get_agent_context(version=n)` pins an older definition. |
| 34 | `revoke_agent_project_access` empties the agent's `project_ids` but the bot stays in `list_project_members` and its existing assignments stay. After a revoke, `create_work_item(assignee_ids=[bot])` **succeeds and silently drops the assignee** (`assignees: []`, no error). `grant_agent_project_access` restores assignment. | tested | After any assignment to an agent, read back `assignees`; if empty, check `get_agent.project_ids`. |
| 35 | Agent fields (`goal_md`, `how_it_works_md`, ...) are stored as given and rendered as Markdown. HTML passed to `goal_md` appears as raw tags in the brief. | tested | Write agent definitions in Markdown. |
| 36 | `update_project_member` can demote the last admin and the project lead (returned role 15). After that, further admin calls (`update_project_member`, `remove_project_member`) return 403, and the permission classifier refused to restore the role from this session. Roles: 20 admin, 15 member, 5 guest. A workspace admin could restore it in the UI. | tested (by accident) | Never change the token owner's or the project lead's role; never run a role change as a probe. Confirm every membership change and name the current admins first. |
| 37 | `add_project_member` accepted an archived agent's bot user (`scratch-qa`); `remove_project_member` removed it. Archived agents still appear in `list_workspace_members` (role 15). | tested | Filter bots by `list_agents(status=active)` before adding them. |
| 38 | `add_work_item_comment` stores `comment_html` unsanitised (a `<script>` tag was kept); `access` is `INTERNAL`; `actor` is the token owner. `update_work_item_comment` works but leaves `edited_at` null. `delete_work_item_comment` works. `list_work_item_comments` is newest first. | tested | Never put untrusted text into comment HTML without escaping it; prefix agent comments with `[handle]`. |
| 39 | `list_work_item_activities` is oldest first, cursor-paged (`per_page` up to 100, `next_page_results`), and lists created, cycle added, relation added (`blocking` on the blocker), state, field changes. It lists links (`created a link`, with the URL in `new_value`) but **not comments** (add, edit and delete of comments left no rows). | tested (corrected after an eval run showed the link row) | For "what changed recently" use `per_page=100` and read to the last page; combine with `list_work_item_comments` for discussion. |
| 40 | `update_estimate_point` changes a value in place (3 to 4) and items keep their point. `update_estimate` renames. `list_estimate_points` is not sorted by `key`. The estimate shows `last_used: false` even when active. | tested | Sort by `key` yourself; changing a value changes the meaning for every item that uses it, so confirm. |
| 41 | `update_module(status=cancelled)` is allowed while the module holds open items, and then `archive_module` works. Archived modules and cycles vanish from `list_modules` / `list_cycles` but their items stay (`list_archived_modules` shows total_issues). `unarchive_module` and `unarchive_cycle` return `{success: true}`. | tested | Say how many open items a module holds before cancelling it. |
| 42 | `archive_cycle` works on a cycle whose end date is in the past, even with no items. `create_cycle` accepts past dates. | tested | Matches #22: "completed" means the end date has passed. |
| 43 | `list_modules` counters (`started_issues`, `unstarted_issues`) undercounted: M1 had 2 started + 2 unstarted items but showed 1 + 1. `list_cycles` counters matched. | tested | Recompute module progress from `list_work_items(module_id=...)`; do not report module counters. |
| 44 | `triage_intake_work_item` takes `work_item_id` = the intake row's `issue` (`issue_detail.id`), not the intake row `id`. Accepting gave status 1, state Backlog, and the item appears in `list_work_items` with the next `sequence_id`. | tested | Use `issue`, not `id`. |
| 45 | `unarchive_project` restores all items (13 of 13 visible again), confirming #1. `get_project_summary` counts included the accepted intake item (`issues` 13) and unarchived modules and cycles. | tested | Reversible; still confirm. |
| 46 | `update_label` renames and re-describes; `create_label(parent_id=...)` nests (`frontend` under `build`). `update_state` renames, recolours and changes the description; the slug follows a rename (`Blocked` renamed to `On Hold` returned slug `on-hold`). | tested | Renaming a state or label changes it for every item; confirm. |
| 47 | `update_work_item(assignee_ids=[...])` returns 200 and **silently drops** agent ids that have no project access, including an archived agent that was already the assignee. Observed twice by an eval run on PMSKX-12: `[archived scratch-developer, scratch-dev2 (access revoked)]` and then `[scratch-dev2]` both came back `assignees: []`, and the item lost its previous assignee. The 400 in #32 applies to paused agents and `accept_assignments=false`, not to a missing access grant. | tested | Before assigning an agent, read `get_agent`: `status`, `accept_assignments` and `project_ids` must allow it. Re-sending the old assignee list can erase it, so `get_work_item` first and report the loss. |
| 48 | A member removed with `remove_project_member` (returned success) was back in `list_project_members` after `archive_project` then `unarchive_project`. The cause (restore of soft-deleted members, or the removal not being durable) was not isolated. | tested (observed); cause untested | Read back `list_project_members` after a removal and again after any unarchive; do not report a removal as final from the first read alone. |
| 49 | When `create_work_item` is called without `assignee_ids`, the project's `default_assignee` (set in project settings, shown by `get_project`) is applied silently: the epic PMSKX-14 came back assigned to the project lead although no assignee was passed. Items created with explicit assignees were unaffected. | tested | If an item must be unassigned, check `get_project.default_assignee` first and say it will be applied; always read back `assignees`. |
| 50 | `add_work_items_to_module` and `add_work_items_to_cycle` return the module's or cycle's **whole membership** (existing items too), not just the items added. `get_project.total_members` counted 1 while `get_project_summary.counts.members` counted 3 (the bots); the summary is the one that includes agents. | tested | Read the response as a membership list, not as a count of what you added; use the summary for member counts. |
