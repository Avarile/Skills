### Defects
- **D1 (medium): `resume.py` shows cleared blockers as open.** After `... status cleared` was appended (append-only), the brief still printed `BLOCKER ... status open`. Resolved blockers cannot be expressed, so every agent brief carries stale blockers.
- **D2 (medium): `ctx-append` breaks Markdown tables.** Appending a row to `## Risk Register` inserted a blank line, detaching the row from the table (see project context). Same blank-line insertion after empty section headings (`## Change Log`, `## Blockers`).
- **D3 (low): `close.py check` reported "`## Estimation Record` section missing"** for an empty section that existed.
- **D4 (low): `close.py stats` on a compressed timeline prints "Actual 0 d ... within declared buffer: True"**, a misleading pass; needs a guard when actual < 1 day or started_at == finished_at for all tasks.

### Gaps (behaviour matches docs but is weak)
- **G1: gate not enforced in `resume`.** With Step 06 (gate) open, the Developer brief listed DO tasks as NEXT. The protocol says "stop and ask", but the tool does not flag it.
- **G2: RAG ignores open blockers and my own AMBER status entry.** With an open high-impact blocker and one task `onhold`, `rollup` said GREEN after the status entry. Matches `reports.md` (only `onhold` >14d turns RED), but contradicts the plain-language status.
- **G3: goal KR average stays 0.0** because `checkin` is a manual step; the finished project does not move KR scores. Expected, but it makes the portfolio view look stalled after a successful close.

### Minor
- `update_record` through MCP returns the whole record (including the long `context`); verbose for agent mode.
- Token is only read from the repo `.env` when sourced; scripts called from other directories fail without it (`CYBERNETICS_DATA_API_TOKEN not set`).
- Skill doc names tools `mcp__cyb-data__*`; in this session they are `mcp__claude_ai_cybernetics-data__*`.
